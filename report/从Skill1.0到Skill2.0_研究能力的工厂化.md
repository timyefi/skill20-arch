## 摘要

**卖方造零件，买方组装车。** 过去卖方研究积累了大量数据库、分析框架与策略思路，买方研究每天面对快速变化的市场，随时有新想法要验证。两者之间天然适合用 AI 打通：卖方把研究成果沉淀成一个个零件，买方不用造轮子，把零件拼起来就能用。这是我们所有工作的底层思想，从 Skill 1.0 到 Skill 2.0，没有改变。

**Skill 1.0 是一件东西。** 一个 skill 装下一整套能力，整体交付，想改需要会技术。

**Skill 2.0 是一盒零件加一张拼装台。** 研究能力被拆成一个个小零件，买方研究者按自己的想法把零件拼起来，不满意说一句大白话，AI 帮着改，越用越顺。本篇讲两层增量：一是研究能力怎么被管起来（生命周期），二是怎么把多条研究能力拼成一个能解决具体投资问题的链条（能力组合）。

**真实案例贯穿全文。** 我们用"流动性 → 机构行为 → 信用利差"三段传导链演示能力组合：资金面环境分档、机构行为拐点、信用利差定价状态，三段各自独立，拼成一张状态面板，回答"环境松紧、机构买卖、利差定价是否同向"。数据全部来自真实数据源，更新到 2026 年 8 月 19—20 日，可追溯、可复现。

**风险提示：** Skill 定义完备性不足；数据源口径变更或更新滞后；AI 辅助分析存在偏差；方法论适用性因机构和市场环境而异。

## 一、从 Skill 1.0 到 Skill 2.0：一件东西到一盒零件

Skill 1.0 解决的是"研究能力能不能封装"的问题。过去机构积累的数据库，物理形态是一个 Excel 文件，一个资金面数据库可能有数十个子表，每个子表是一组分析视角，里面嵌着插件取数、计算公式、阈值判断和图表模板。分析师每周打开它，手动刷新、肉眼看数、手写点评。Skill 1.0 做的事情，是把这些 Excel 数据库拆成 AI 能读懂、能直接执行的 skill 文件。这个阶段，研究能力被封成了一个个整体：一个 skill 就是一整套能力。

到了 Skill 2.0，我们要回答的是另一个问题：研究能力已经有很多了，**怎么把它们管起来、怎么按一个投资问题把它们拼起来用**。这是两件新事：

- **管起来**：一堆 skill 不能靠人脑记。谁更新了、版本是什么、敏感信息有没有泄漏、结果靠不靠谱，这些要有一个成体系的机制。这一半是卖方（提供零件的人）要做的。
- **拼起来**：一个具体的投资问题，往往要动用多条研究能力。买方研究者是那个拼装的人。拼装要足够简单，简单到说一句大白话就能完成。

这两件新事，对应 Skill 2.0 的两条腿：生命周期管理，和能力组合。

## 二、生命周期：卖方造好零件，买方拿来就用

把研究能力从"一件东西"变成"一盒零件"，生命周期要做五件事。其中前两件是卖方（零件生产者）的事情，一笔带过；后三件是买方（零件使用者）天天打交道的，详细展开。

### 卖方侧：造零件、摆上架

**造零件。** 把研究成果做成零件，有统一模板。一个数据库 skill 就是几个文件的组合：SKILL.md 相当于 sheet 目录，告诉 AI 这个数据库有哪些视角、什么场景下该调用；data_contract.yaml 相当于插件的取数连接，每个视角要什么字段、什么频率、对应哪个取数代码和参数；公式文件相当于子表里的公式，利差怎么减、分位怎么算、评分卡怎么打，逐个写清楚；阈值文件相当于分析师脑子里的经验判断，多少算偏紧、多少算偏宽；模板目录里放图表脚本和点评模板。目前我们已经用同一套模板做出 13 个主题数据库、约 500 个分析逻辑。

**摆上架。** 零件做好、装好，发布出去。发布到什么商店、怎么安装到各平台，是作者自己的事，用户不需要关心。用户拿到的，是装好、能直接用的东西。

### 买方侧：拿来用、验一验、说一声就改

买方真正打交道的，是三件事。

**拿来用。** 挑需要的零件直接用，不用懂里面怎么实现。说一句要什么，AI 取数、计算、出图全包。以前买方想用一套数据库，得先学会整套东西怎么操作；现在只要说清楚要什么，剩下的交给 AI。一个资金面数据库有三十多个视角，买方只需要其中几个，按需取用，不必加载全部。

**验一验。** 结果靠不靠谱，有办法查。每个能力背后有基准线——一组历史合理区间。结果落在极端位置会自动报警，先查数据链路，再信结论。算出来的东西每次都能复现，不怕别人问"这个数怎么来的"。研究里最怕的不是错，是错了不知道错在哪、别人无法复核。基准线和可复现，让"结果可核查"成为默认动作。

**说一声就改。** 不满意用大白话提，AI 改。改逻辑不用写代码，在对话里说一句"这里按 XX 逻辑改一下"，AI 去改对应的部分。视角能单独更新，一处维护、用到它的地方一起受益。以前改一个分析视角要动整个数据库，现在改的是其中一个零件，其他部分不受影响。研究的经验，就在一次次"说一声就改"里沉淀下来，越用越贴合自己。

## 三、能力组合：把一个想法变成结果

生命周期解决了"零件怎么管理"，能力组合解决"零件怎么拼"。把一盒零件拼成一个能解决具体投资问题的链条，走四步，每一步都是大白话。

<!-- figure: single -->
![能力组合：把一个想法变成结果（四步）](images/fig_composer.png)
<!-- source: 资料来源：国投证券证券研究所，WIND，同花顺 -->

**第一步，想清楚要看什么。** 一个具体的投资问题。比如"资金面紧了，机构会不会开始卖，信用利差会不会走阔"。问题越具体，能拼出的链条越清楚。

**第二步，挑零件。** 看哪些研究能力能帮上。资金面取一段，机构行为取一段，信用利差取一段。挑零件不动任何零件内部——每个零件都是装好的，拿来即用。

**第三步，拼起来跑一遍。** 三段接起来，端到端跑通，得到一张图、一张表、一段点评。每一步留痕，跑过就能复现。

**第四步，不满意就说。** 说一句大白话，AI 改。改好的这套拼法，可以存下来，下次直接再用，变成你自己的东西。

能力组合的价值在于：**一个投资问题，不是重新造一遍轮子，而是把现成零件按问题拼起来。** 拼装足够简单，买方研究者才有余力把精力放在判断上，而不是放在取数、计算、对账上。

## 四、真实案例：流动性 → 机构行为 → 信用利差

我们用能力组合把三段研究能力拼成一条传导链：资金面环境分档 → 机构行为拐点 → 信用利差定价状态。三段各自独立、各自有真实数据源，拼在一起回答一个问题：环境的松紧、机构的买卖、利差的定价，是不是在同一条线上。

### 资金面段：环境分档

资金面数据库把存单收益率、分层、季节性等几十个视角做成零件。这里取收益率序列，分档判断流动性环境松、中、紧。

<!-- figure: single -->
![资金面分档：存单收益率近30日走势（1M/3M/6M）](images/fig_fund.png)
<!-- source: 资料来源：国投证券证券研究所，WIND，同花顺 -->

最新数据（2026-08-20）：1M 存单收益率 0.50%，分档为**松**。近 30 日 1M 收益率在 0.38%—0.88% 之间，整体处于低位，流动性环境宽松。

### 机构行为段：谁在买、谁在卖

机构行为数据库把 8 类机构 × 5 类券种的日度净买入做成零件。取最近交易日各机构净买入和周环比，看谁在买、谁在卖、是否转向。

<!-- figure: single -->
![机构行为：主要机构现券净买入与周环比（亿元）](images/fig_beh.png)
<!-- source: 资料来源：国投证券证券研究所，WIND，同花顺 -->

最新数据（2026-08-19）：大型银行净卖出 171.2 亿元、周环比继续减 82.7 亿元；中小型银行净卖出 575.2 亿元、周环比减 834.4 亿元；证券公司净卖出 281.4 亿元。与此同时，基金公司及产品净买入 332.8 亿元、周环比加 552.2 亿元；其他机构净买入 529.3 亿元。**银行与券商在减持，基金与其他在买入——机构行为出现明显分歧。**

### 信用利差段：定价状态

信用利差数据库把各评级、各期限的收益率曲线做成零件。取中短票 AAA、AA、AA- 与国债的利差，看定价状态。

<!-- figure: single -->
![信用利差定价：AAA/AA/AA- 3Y 相对国债利差（bp）](images/fig_spread.png)
<!-- source: 资料来源：国投证券证券研究所，WIND，同花顺 -->

最新数据（2026-08-20）：AAA 3Y 利差 34.9bp，AA 3Y 利差 51.9bp，AA- 3Y 利差 99.9bp。利差整体处于中性区间，信用定价平稳。

### 拼起来：传导链状态面板

三段拼成一张状态面板，回答"环境松紧、机构买卖、利差定价是否同向"。

<!-- figure: single -->
![传导链状态面板：流动性 → 机构行为 → 信用利差](images/fig_panel.png)
<!-- source: 资料来源：国投证券证券研究所，WIND，同花顺 -->

**面板结论（2026-08-19/20）：** 资金面松（1M 0.50%）；机构行为分歧——银行、券商减持，基金、其他买入；信用利差平稳（AAA 3Y 34.9bp、AA- 3Y 99.9bp）。三段并不同向：环境宽松，但银行与券商在主动降杠杆，基金与其他在承接；利差尚未因机构分化而明显走阔。**对买方研究者的含义：当前环境下机构行为比利差定价更值得跟踪，银行与券商减持的持续性，是判断信用利差是否走阔的前置信号。**

这个案例的关键不在三段各自的结果，而在拼装本身：三个数据库零件，没有任何一个为这个特定问题而建，拼在一起就能回答一个具体的投资问题。这正是能力组合想讲的事情。

## 六、讨论

### 与已有工作的关系

本文建立在之前工作的基础上，但不重复之前讲过的内容。中间件架构（四层：数据、逻辑、回测、输出）解决的是研究能力怎么拆的问题，已有专门报告和架构总览页详细说明；各具体中间件手册解决的是单个中间件怎么组织的问题。本文讲的是这两层之上的第三件事：一堆研究能力怎么管、怎么拼。**卖方造零件、买方组装车，这个底层思想从 Skill 1.0 到 Skill 2.0 一以贯之，是值得反复讲的。**

### 局限

- 生命周期管理依赖卖方持续维护零件质量，零件本身定义不完整时，组合结果的可靠性会打折扣。
- 能力组合的价值依赖零件库的丰富程度。零件越多、越标准，拼装越高效。
- 真实案例展示了组合方法，但案例中的三段数据为截面快照，传导关系的统计验证需要更长时间序列。

## 七、结语

从 Skill 1.0 到 Skill 2.0，变化不是重写一遍，而是把研究能力从"一件东西"升级为"一盒零件"：生命周期让零件可管理，能力组合让零件可拼装。卖方造零件，买方组装车——这个底层思想没有变，变的只是零件的丰富程度和拼装的容易程度。真实案例告诉我们，把资金面、机构行为、信用利差三个零件拼起来，就能回答一个具体的投资问题。这，就是 Skill 2.0 想讲的事情。

## 风险提示

**Skill 定义完备性不足：** skill 文件的取数契约、计算公式、阈值判断均依赖人工定义，若定义存在遗漏或偏差，AI 输出结果可能失真，需持续校验和迭代。

**数据源口径变更或更新滞后：** skill 中间件依赖外部数据源，若数据源调整指标口径、接口参数或更新频率，可能影响分析结果的准确性和时效性。

**AI 辅助分析存在偏差：** AI 在理解复杂市场逻辑、处理极端行情和结构性变化时存在局限，skill 化分析不能完全替代研究员的专业判断，实际应用中需结合人工审核。

**方法论适用性因机构和市场环境而异：** 本文所述方法论为固收研究方法论的工程化探索，不同机构的研究积累、数据条件、投研流程存在差异，照搬套用可能水土不服。
