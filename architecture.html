Chapter 01 · System Overview

系统总览：从「整体技能」到「模块化中间件」

Skill 1.0 是全局可用的整体技能：一个大的技能包，整体加载、内部黑盒、随写出或随人走。Skill 2.0 把它升级为模块化中间件——沿「数据源 → 取数 → 知识 → 计算 → 输出」五层纵向拆开，每一层、每一个模块都有独立接口，Skill 不必全局可用，清晰拆成一个部分就能为所用。

一句话总纲
「只取一个模块」是 Skill 2.0 的核心用法。卖方积累基础组件（基础设施），买方组装策略；数据源契约化切换，知识层用市场回验驱动更新（框架 > 具体数值）。本手册的「拆解」本身就是 Skill 2.0 的一次实例化——把一个大 skill 的手册拆成「分层架构 + 模块注册表（接口契约）+ 独立调用示例 + 集成模式」。

Chapter 03 · Module SKILL.md

SKILL.md：激活指令与场景路由

一句话定位：技能的中枢神经——不做计算、不存数据，只负责判断「这句任务该路由到哪一类模块」，再吐出激活指令让 Agent 按契约组装。

接口契约
IN用户场景描述 / 触发词（自然语言）
OUT场景路由表 + 激活指令（读取哪些模块、执行顺序）
DEPknowledge/ · templates/ · data_contract · scripts/ · config/

输出 Schema · 场景路由

SKILL.md 的输出是一张「场景 → 模块清单」的路由表：

路由表（示意 Schema）
## 场景路由（Skill 2.0 中间件）
| 用户场景                | 装载模块                                             | 顺序               |
|------------------------|-----------------------------------------------------|--------------------|
| "信用利差周报"          | data_contract → scripts → knowledge → templates     | 取数→计算→知识→输出 |
| "查某个指标公式"        | knowledge 仅读（零取数）                              | 单模块             |
| "只要某主题原始数据"    | data_contract → scripts/fetch 仅取数                | 单模块             |
| "换数据源复跑一遍"      | data_contract → scripts（换源）→ 复用后续层          | 局部替换           |

独立使用 · 最小示例

只读路由：Agent 加载 SKILL.md 后第一步
# Agent 引导（SKILL.md 内嵌）
1. 读取 SKILL.md 的 frontmatter：name / 场景 / 依赖清单
2. 命中场景 → 按路由表装载对应模块路径
3. 模块间通过 data_contract 契约衔接，不跨层读脏数据
4. 每一步输出落到 output/，文件名带 YYYYMMDD
替换策略
场景路由是声明式的——改写路由表即可把同一套模块重新编排成新品（例如同一批取数+计算模块，路由到「日报」或「周报」模板）。替换 SKILL.md 本身不影响任何模块的接口。
Chapter 04 · Module knowledge/

知识层：公式 · 阈值档位 · 历史案例

一句话定位：方法论大脑——纯静态 Markdown 文件，存「怎么看、怎么算、怎么解读」，不依赖任何运行时，用市场回验驱动更新。

接口契约
IN指标名 / 查询意图
OUT公式定义 / 阈值档位 / 市场案例解析
DEP—（纯静态，零运行时；可被 scripts 只读引用）

输出 Schema · 知识条目

knowledge 条目 Schema（JSON 表示）
{
  "indicator": "信用利差_AAA_3Y",
  "definition": "CS = Y_credit(同评级同期限) − Y_国开债(同期限)",
  "bands": {"tight": "< 20bp", "neutral": "20~35bp", "loose": "> 55bp"},
  "logic": "框架 > 数值：档位仅作起点，须逐年用分位数回验校准",
  "case": "2024-2025 资产荒：中枢系统性下移，档位整体下调 5~10bp"
}

独立使用 · 最小示例

只查知识：Agent 或人直接读文件，零取数
# 人工/Agent 直接读取
grep "信用利差_AAA_3Y" knowledge/views.md
grep "评分卡" knowledge/framework.md
ls knowledge/cases/   # 历史案例库（回验素材）
替换策略
knowledge 是preserve文件——同步更新技能时保留用户版本。卖方维护「基础框架库」，买方把自己的立场、阈值、案例写进各自的 knowledge 副本。knowledge/ 整个目录删掉，其余四类模块依然能取数与计算（只是失去解读能力）。

IN结构化数据对象（来自 scripts/compute 输出）
OUTHTML 看板 / PNG 图表 / MD 文字段落
DEP计算层数值（弱依赖，可手工填充）

独立使用 · 最小示例（只用模板）

已有数据，只做输出形态切换

data = {"cs_AAA_3Y": 21.4, "cs_AAp_5Y": 47.2}

替换策略
输出形态切换 = 换模板文件，数据与计算层零改动。想从「文字点评」改出「周报表格」「HTML 看板」「PNG 图」，只需准备多套模板并更新 SKILL.md 的路由。模板层甚至可以单独拷走，套用自己的数据源结果。
Chapter 06 · Module data_contract

契约层：字段契约，数据源无关

一句话定位：全库的巴别塔翻译官——把「中债登的字段名」与「iFinD 的 M码」翻译成统一的业务字段，让上层不关心数据来自哪家。数据源契约化切换的根基就在这一层。

接口契约
IN—（声明式配置）
OUT统一字段名 / 类型 / 单位与精度 / 口径说明
DEP—（与数据源完全解耦）

输出 Schema · data_contract.yaml

字段契约（示意）
fields:
  credit_ytm_aaa_3y:
    business_name: "中短票 AAA 3Y 收益率"
    type: float
    unit: "%"
    source_map:            # 数据源无关的关键
      chinabond: "CCC_YTM_AAA3Y"
      ifind:     "M0016xxxxxx"
      akshare:   "bond_zh_us_rate"
  yield_ref_3y:
    business_name: "国开债 3Y 收益率"
    unit: "%"
    source_map:
      ifind: "M00xxxxxxx"

独立使用 · 最小示例

换数据源时只改这一层 + 取数引擎配置
from data_contract import load
c = load("data_contract.yaml")
print(c["credit_ytm_aaa_3y"]["source_map"]["ifind"])  # M码
# 上层脚本只认业务名 credit_ytm_aaa_3y，字段名永不变
替换策略
新增 / 切换数据源（如中债登直连、自有底稿 Excel），只需在契约里补一段 source_map 并实现对应取数适配——knowledge、计算层、模板层零改动。这正是「卖方做基础设施、买方组装策略」的组织方式。
Chapter 07 · Module scripts/

引擎层：取数引擎 + 计算引擎

一句话定位：唯一会执行代码的层——取数引擎按契约字段去数据源取数，计算引擎按知识层公式算指标。两者各自独立，可只取数、只计算，或整段替换。

接口契约
IN凭证(config) + 契约字段名 + 日期区间
OUT统一 DataFrame / 结构化指标
DEPdata_contract（字段映射）· config（阈值）· 数据源凭证

取数引擎 · 最小示例

只取数：独立于知识层与模板层
from scripts.fetch import Fetcher
f = Fetcher(source="ifind")            # 凭证读自 config，绝不硬编码
df = f.fetch(["credit_ytm_aaa_3y","yield_ref_3y"], "20260717", "20260821")
# → DataFrame[date, credit_ytm_aaa_3y, yield_ref_3y]（列名即契约业务名）

计算引擎 · 最小示例

只计算：把取来的 YTM 减成利差 + 分位数
from scripts.compute import spread, percentile
cs = spread(df)                        # CS = Y_credit − Y_国开（契约公式）
p  = percentile(cs, history=df_hist)   # 历史分位数（回验基础）
band = band_of(p)                      # 读 config 阈值档位 → tight/neutral/loose
替换策略
scripts 是实现可换、签名不变的模块：只要新引擎遵守「IN 契约字段 / OUT 统一列名」，整段重写或换成别的语言实现都行。凭证一律经 config 注入，引擎代码内不得出现任何账号 / 密钥。
Chapter 08 · Module config/

配置层：阈值参数 · preserve 模式

一句话定位：旋钮面板——所有阈值与参数集中配置，设计为 preserve 模式：技能更新时保留用户覆盖值，只补新的默认值。

接口契约
IN参数名
OUT阈值档位 / 参数取值
DEP—（preserve，用户可覆盖；被计算引擎只读）

输出 Schema · config/thresholds.yaml

三档阈值（示意；框架 > 数值）
credit_spread_aaa_3y:
  tight:  20     # bp 以下：偏贵
  neutral: [20, 55] # 中性区间
  loose:  55     # bp 以上：便宜
  note: "资产荒年份整体下调 5~10bp，用历史分位数回验校准"

独立使用 · 最小示例

覆盖阈值后再跑计算
# 用户把自己的阈值写进 config/，不动任何代码
from config import load
cfg = load("config/thresholds.yaml")
print(cfg.scaled(spread=18))   # → tight（18 < 20）
替换策略 + 更新纪律
config 是用户唯一被点名「可以改」的地方。技能更新只补默认档位（preserve），不覆盖用户值。阈值永不硬编码进脚本或知识层，保证「改旋钮、不改机器」。
Chapter 09 · Integration Patterns

集成模式：四种接入深度

不必把 Skill 装成全局可用的整体。按场景选择接入深度——从「全流程」「只取一个模块」到「数据源替换」「输出形态切换」。

适用：周报组装、策略专题、例行看板

走完整五层管线：SKILL.md 路由 → 契约取数 → 知识+配置判读 → 计算引擎 → 模板输出。一次成型即可交付。

全流程 Prompt
"按 Skill 2.0 中间件跑一遍信用利差周报：
 取数 → 计算 → 用 knowledge 解读 → 输出 HTML 看板 + 文字点评。"

涉及层：L0–L4 全部 · 产物：HTML + PNG + MD 全套

适用：别的 skill 只要一段知识 / 一份数据 / 一个模板

「只取一个模块」是 Skill 2.0 的核心用法。例如买方只需要卖方沉淀的「评分卡框架」，拷 knowledge 一个文件即可，不触碰取数与计算。

只取一个模块：仅查知识
# 只取 knowledge/framework.md（评分卡框架），零依赖
grep "评分卡" knowledge/framework.md

涉及层：单层 · 产物：规则 / 数据 / 模板文件

适用：换数据源复跑（中债登 ⇄ iFinD ⇄ AKShare ⇄ 自有底稿）

只改契约的 source_map 与取数引擎配置，知识、计算、模板全部复用——数据源契约化切换。

换源示例
from scripts.fetch import Fetcher
f1 = Fetcher(source="ifind")              # 原源
f2 = Fetcher(source="chinabond")         # 换源：同一个 Fetcher 接口
df = f2.fetch(["credit_ytm_aaa_3y"], ...)

涉及层：L0–L1 + data_contract · 产物：同一套下游产物

适用：同一数据，换输出形态交付

数据与计算复用，只换 templates/：同一天的利差数据，可同时出「周报表格」「HTML 看板」「PNG 图」「文字点评」。

形态切换示例
from templates.render import render
render(data, "templates/weekly_table.html",  "out/w_table.html")
render(data, "templates/dashboard.html",   "out/w_dash.html")
render(data, "templates/commentary.md",   "out/w_cmt.md")

涉及层：L4 · 产物：多形态交付物

集成深度对比

模式涉及层 / 模块运行时依赖凭证需求典型产物
① 全流程L0–L4 全部requests + pandas + matplotlib（+ 模板运行时）按数据源配置HTML + PNG + MD 全套
② 只取一个模块单模块（如 knowledge/）无无规则 / 数据 / 模板
③ 数据源替换L0–L1 + data_contractrequests / 对应源 SDK新源凭证（config 注入）同一套下游产物
④ 输出形态切换L4 templatesminimal（渲染器）无多形态交付物
选择建议
不确定时从 ② 只取一个模块 开始——先拿走最想要的知识/数据/模板，跑通后按需向两侧扩展。Skill 2.0 不给集成者设门槛：Skill 不必全局可用。
Chapter 10 · Knowledge Writing Principles

知识层写作原则：框架 > 数值，鼓励回验

知识层最容易写错的地方是把一堆「拍脑袋的阈值」写成金科玉律。正确的写法是提供可复用的判断框架（维度划分 + 方向 + 结构），并强烈要求用市场回验驱动阈值更新。

核心立场
下表提供的是一套可复用的判断框架，而非固定知识。推荐做法：用历史序列做市场回验，用数据驱动替代经验拍脑袋。config 设计为 preserve（用户可覆盖），knowledge 允许任何人改写为自己的版本。

写作四问（写每个知识条目前自检）

#问题正例 / 反例
1给框架还是给数值？✅ 提供维度划分与判断方向；❌ 只复制一串「经验阈值」
2数值能被回验吗？✅ 标注取样区间与口径；❌ 无来源、无区间的孤立数字
3事件案例有观察窗口吗？✅ 「永煤/化债前后中枢漂移 X bp」；❌ 无上下文的一句话结论
4更新机制说清了吗？✅ 给出回验流程 + config preserve 说明；❌ 宣称阈值「永远不变」

Chapter 11 · Potential Applications

潜在应用：从中间件到研究产出

Skill 2.0 模块化中间件本身不是终点——六类模块 × 五层 × 数据源契约组合起来，可以支撑三类高阶应用（已由 BondClaw 固收体系 13 个主题数据库、约 500 个分析逻辑验证）。

应用 A
市场复盘
用历史序列还原「当时市场在交易什么」
IN取数引擎 + knowledge + config 阈值
OUT周度/月度/年度复盘 + 事件时间线
  • 周度：各视角环比 + 驱动归因
  • 月度：中枢漂移 + 分位变迁 + 行业排名
  • 事件复盘：前后各视角信号传导时间线
应用 B
规律挖掘
从长序列发现可重复的统计规律
IN3–5 年序列 + 事件标注（knowledge/cases）
OUT季节性图谱 / 条件概率 / 领先滞后
  • 季节性：季末理财赎回 → 利差走阔
  • 条件概率：事件后 N 日内走阔概率
  • 领先滞后：舆情/事件领先定价 X 月
应用 C
策略探索与回测
把阈值框架转成可回测的交易信号
IN阈值框架 + 评分卡 + 历史序列
OUT信号序列 / 回测收益 / 参数敏感性
  • 分位数策略：>80% 分位买入 / <20% 卖出
  • 评分卡择时：得分 → 久期/评级建议
  • 参数搜索：阈值档位 + 持有期 N 网格
从信号到 Alpha 的路径
中间件提供原始信号（指标、分位、评分）；规律挖掘把信号转成条件概率；回测把条件概率转成可执行规则并验证经济显著性——三层递进。卖方积累基础组件，买方组装策略，分工由此展开。
